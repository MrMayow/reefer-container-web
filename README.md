# Размещение рефрижераторных контейнеров

Веб-приложение распределяет контейнеры по площадкам с минимальной стоимостью. Можно задать данные вручную, сгенерировать пример, перетаскивать контейнеры и сравнивать три метода поиска. Все числовые параметры задаются целыми числами.

## Запуск

Нужен Python 3. Дополнительные пакеты не требуются. Откройте PowerShell в папке проекта:

~~~powershell
py -3 app.py
~~~

Откройте http://127.0.0.1:8000/ . Остановка сервера — Ctrl+C. Если порт занят, запустите «py -3 app.py 8001» и откройте порт 8001. После изменения Python-файлов перезапустите сервер. Открывать HTML-файл напрямую не нужно: браузер обращается к Python-серверу.

## Работа с Git

Проект находится в приватном репозитории [MrMayow/reefer-container-web](https://github.com/MrMayow/reefer-container-web). Рабочая папка — reefer-container-web. После изменений:

~~~powershell
git status
git diff
py -3 -B -m unittest -q
git add .
git commit -m "Описание изменения"
git push
~~~

Если изменения появились на GitHub или другом компьютере, перед работой выполните «git pull --ff-only». Ветка main хранит исходный вариант; отдельные изменения можно делать в новых ветках.

## Использование

1. Перетащите контейнер на площадку мышью или пальцем. Другой способ — нажать контейнер, затем площадку. Назначение также меняется в таблице стоимости. Сумма и нарушения пересчитываются.
2. Измените параметры в таблицах или нажмите «Сгенерировать». Одинаковое зерно генерации создаёт одинаковые данные. Генерация заменяет текущий набор.
3. Выберите метод, задайте его настройки и нажмите «Запустить». После расчёта появятся график, ползунок этапов, счётчики и размещение контейнеров. Кнопка «Применить лучший план» переносит найденный вариант на схему. Во время полного перебора показываются число проверенных назначений, средняя скорость, прошедшее и примерное оставшееся время. Кнопка «Остановить» прерывает расчёт без результата.

Изменение параметров сбрасывает результаты старых запусков. Ручное перемещение сохраняет их для сравнения. Обновление страницы возвращает исходный пример; постоянное сохранение данных пока не предусмотрено.

## Условия и стоимость

Каждый контейнер должен быть назначен ровно на одну площадку. На площадке ограничены число мест, суммарная масса и мощность. Для каждого контейнера проверяется срок: время хранения + время перевозки не больше предельного времени.

Стоимость контейнера равна времени хранения × тарифу хранения + стоимости перевозки. Для перевозки есть два режима: тариф за контейнер-час или тариф за тонну-час. Во втором режиме стоимость перевозки дополнительно умножается на массу контейнера. Если план нарушает ограничения, показанная сумма не считается допустимым решением.

## Методы поиска

- **Генетический алгоритм** создаёт допустимые планы, скрещивает их и меняет назначения. В настройке «Отбор родителей» можно выбрать турнир из трёх случайных планов (побеждает самый дешёвый; режим по умолчанию) или выбор родителей из лучшей половины популяции после сортировки по стоимости. Мутации можно выключить или выбрать один тип: перенос одного контейнера либо обмен площадками двух контейнеров. Вероятность попытки мутации для каждого потомка задаётся целым числом от 0 до 100%; по умолчанию это 60% и включён обмен. Лучший план сохраняется в каждом поколении. График показывает лучшую стоимость по поколениям. Найденный план не является доказанным глобальным оптимумом.
- **Ветви и границы** перебирает назначения и отсекает ветви, которые не могут улучшить лучший план. Отдельный график показывает число отсечений. После завершения всего поиска метод доказывает оптимум или отсутствие допустимого решения. При достижении лимита узлов доказательства нет. Результат генетического алгоритма передаётся как начальный план только при установленной отметке.
- **Полный перебор** проверяет все назначения без отсечения и без лимита проверок. После проверки всех вариантов результат доказан. Для 12 контейнеров и 3 площадок всего 3¹² = 531 441 назначение. Время работы быстро растёт с числом контейнеров и площадок: для N контейнеров и M площадок нужно проверить Mᴺ назначений.

Для полного перебора сервер передаёт прогресс примерно дважды в секунду; остальные методы возвращают историю этапов после окончания расчёта. Оценка оставшегося времени приблизительная: скорость меняется из-за разной сложности проверяемых назначений. Для перебора используется стандартный `itertools.product`; дополнительные пакеты не нужны.

## Файлы

| Файл | Назначение |
| --- | --- |
| app.py | Локальный HTTP-сервер и маршруты API |
| model.py | Генерация данных, ограничения и расчёт стоимости |
| genetic.py | Генетический алгоритм |
| branch_bound.py | Метод ветвей и границ |
| exhaustive.py | Полный перебор |
| static/index.html | Поля и блоки страницы |
| static/style.css | Оформление |
| static/app.js | Действия пользователя, запросы и визуализация |
| test_*.py | Проверка модели и методов поиска |

Браузер отправляет данные задачи на /api/evaluate для пересчёта. Запуск метода отправляет те же данные на /api/solve. Для полного перебора сервер передаёт строки JSON с прогрессом и окончательным ответом. Для других методов он возвращает один ответ JSON. JavaScript показывает данные на странице.

## Проверка

~~~powershell
py -3 -B -m unittest -q
~~~

Тесты проверяют ограничения, обе формулы тарифа, допустимость найденных планов, полный перебор более миллиона назначений и статусы точных методов.
