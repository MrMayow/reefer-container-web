# Размещение рефрижераторных контейнеров

Веб-приложение распределяет контейнеры по площадкам с минимальной стоимостью. Можно задать данные вручную, сгенерировать пример, перетаскивать контейнеры и сравнивать три метода поиска. Параметры задачи задаются целыми числами, вероятность мутации — числом от 0 до 1.

## Запуск

Нужен Python 3. Дополнительные пакеты не требуются. Откройте PowerShell в папке проекта:

~~~powershell
py -3 app.py
~~~

Откройте http://127.0.0.1:8000/ . Остановка сервера — Ctrl+C. Если порт занят, запустите «py -3 app.py 8001» и откройте порт 8001. После изменения Python-файлов перезапустите сервер. Открывать HTML-файл напрямую не нужно: браузер обращается к Python-серверу.

## Использование

1. Перетащите контейнер на площадку мышью или пальцем. Другой способ — нажать контейнер, затем площадку. Назначение также меняется в таблице стоимости. Сумма и нарушения пересчитываются.
2. Измените параметры в таблицах или нажмите «Сгенерировать». Одинаковое зерно генерации создает одинаковые данные. Генерация заменяет текущий набор.
3. Выберите метод, задайте его настройки и нажмите «Запустить». После расчета появятся график, ползунок этапов, счетчики и размещение контейнеров. Кнопка «Применить лучший план» переносит найденный вариант на схему. Во время полного перебора показываются число проверенных назначений, средняя скорость, прошедшее и примерное оставшееся время. Кнопка «Остановить» прерывает расчет без результата. Поле «Процессы» задает число одновременно работающих процессов; 0 выбирает число автоматически.

Изменение параметров сбрасывает результаты старых запусков. Ручное перемещение сохраняет их для сравнения. Обновление страницы возвращает исходный пример; постоянное сохранение данных пока не предусмотрено.

## Условия и стоимость

Каждый контейнер должен быть назначен ровно на одну площадку. На площадке ограничены число мест, суммарная масса и мощность. Для каждого контейнера проверяется срок: время хранения + время перевозки не больше предельного времени.

Стоимость контейнера равна времени хранения × тарифу хранения + времени перевозки × тарифу перевозки. Тариф перевозки задается за час перевозки одного контейнера; масса используется только в ограничениях площадки. Формула соответствует исходной записи `c_ij = t_i × h_j + T_j × d_j`. Поле «Срок перевозки и хранения, ч» задает предел `C` для каждого контейнера: `t_i + T_j ≤ C`. Если план нарушает ограничения, показанная сумма не считается допустимым решением.

## Вероятность мутации

Поле и API используют одну шкалу: от 0 до 1. Значение 0 отключает попытки мутации, 1 вызывает попытку для каждого подходящего потомка, 0,6 означает шанс 60%. В JSON используется точка: `"mutationProbability": 0.6`. Отдельная попытка может не дать допустимого изменения; потомки, отклоненные до этапа мутации, в ней не участвуют. Прежние значения вроде 60 теперь отклоняются сервером.

## Методы поиска

Настройка «Размер популяции» в генетическом алгоритме задает верхний предел количества разных планов в одном поколении. Алгоритм старается набрать это количество, но может использовать меньше планов, если за ограниченное число попыток собрать полный набор не удалось. Например, при пределе 36 фактическая популяция может содержать 8 планов. Это не означает, что всего существует только 8 допустимых размещений.

При создании начальной популяции уже найденные планы исключаются внутри поиска, чтобы возвращаться к другим назначениям. На старт отведено до 20 попыток на каждое заданное место, до 100 000 проверок назначений за одну попытку и до 50 000 000 проверок суммарно. Поиск заканчивается раньше, если набрана популяция или полностью проверены все оставшиеся варианты. В этапе 0 показаны число попыток и проверок начального поиска. В режиме «Лучшая половина» эта половина служит источником родителей: пары могут выбираться многократно, поэтому число потомков может превышать число родителей. Размер следующих поколений ограничивается заданным максимумом.

- **Генетический алгоритм** создает допустимые планы, скрещивает их и меняет назначения. При создании планов он возвращается к предыдущим контейнерам и пробует другие площадки, если текущий выбор приводит к тупику; это помогает получить разные планы при тесных ограничениях. В настройке «Отбор родителей» можно выбрать турнир из трех случайных планов (побеждает самый дешевый; режим по умолчанию) или выбор родителей из лучшей половины популяции после сортировки по стоимости. Мутации можно выключить или выбрать один тип: перенос одного контейнера либо обмен площадками двух контейнеров. Вероятность попытки мутации для каждого потомка задается числом от 0 до 1; попытка не гарантирует допустимое изменение. По умолчанию это 0,6 и включен обмен. Лучший план сохраняется в каждом поколении. График показывает лучшую стоимость по поколениям. Генетический поиск не гарантирует нахождения плана с минимальной стоимостью.
- **Ветви и границы** перебирает назначения и отсекает ветви, которые не могут улучшить лучший план. Отдельный график показывает число отсечений. После завершения всего поиска метод подтверждает минимальную стоимость или отсутствие допустимого решения. При достижении лимита узлов доказательства нет. Начальный ориентир — стоимость текущего размещения, если оно допустимо.
- **Полный перебор** проверяет все назначения без отсечения и без лимита проверок. Большие задачи распределяются между несколькими процессами, чтобы использовать ядра процессора. Для небольших задач автоматический режим выбирает один процесс, потому что запуск дополнительных процессов может быть медленнее самого поиска. После проверки всех вариантов результат доказан. Для 12 контейнеров и 3 площадок всего 3¹² = 531 441 назначение. Время работы быстро растет с числом контейнеров и площадок: для N контейнеров и M площадок нужно проверить Mᴺ назначений.

В генетическом алгоритме каждая популяция содержит только разные допустимые планы. Исправление пропускает уже добавленные размещения; после мутации потомок также проверяется на повтор. Лучший план сохраняется отдельно по правилу элитизма. Турнир при небольшой популяции использует до трех участников.

В одной паре всегда два разных плана. Первый родитель выбирается обычным способом, затем временно исключается из выборки второго. При турнире он не участвует и во втором турнире этой пары. Между разными парами родители и пары могут повторяться. Если доступно меньше двух родителей, скрещивания и мутации потомков прекращаются, а свободные места заполняются резервом и построением дополнительных планов. При лучшей половине из двух или трех фактических особей родительская группа содержит только одну: скрещивания пропускаются, нижняя половина остается резервом.

При исправлении для каждого контейнера сначала пробуется площадка, полученная от родителей. Другие площадки проверяются, если это назначение или его продолжение нарушает ограничения либо приводит к исключенному плану. Так исправление старается сохранить назначения потомка; минимальное число изменений не гарантируется. Лимит остается равным 5 000 проверкам назначений за попытку.

График показывает лучший найденный результат, поэтому горизонтальный участок не означает, что популяция перестала меняться. «Новых планов» — число особей выбранного поколения, которых не было в предыдущем. «Поколений без улучшения» — число подряд идущих переходов до выбранного поколения без уменьшения лучшей стоимости. Эти показатели не меняют критерий остановки: выполняется заданное число поколений. Если уже найдена минимальная стоимость, дальнейшее плато закономерно; сам генетический алгоритм это не доказывает.

### Повторение популяций

Блок «Лучший план поколения» под счетчиками показывает одно размещение — лучшее к этому этапу. Он может повторяться при разных популяциях. Все особи доступны в раскрывающемся блоке поколения: «Итоговая популяция». Показатель «Новых планов» сравнивает весь состав с предыдущим поколением.

Запрет копий действует внутри одного поколения. План прошлого поколения может снова получиться при скрещивании или исправлении, пока он не выбыл. Резерв также переносит прежние планы. Поэтому новая популяция иногда целиком состоит из старых особей, даже если в задаче есть другие допустимые размещения. Если все места заполнены, обычный заключительный добор не запускается.

Теперь после поколения без новых особей следующий шаг начинается так:

1. Сохраняется лучший план.
2. До скрещиваний выполняется одна попытка построить новый допустимый план с пределом 100 000 проверок назначений. Из поиска исключены вся прежняя популяция и все выбывшие планы этого запуска. Перестановка строк популяции не считается обновлением.
3. Если план найден, он занимает одно место в новой популяции. Остальные места заполняются обычным способом: потомками, резервом и добором. Заданный размер не превышается. Родители по-прежнему берутся только из прежней популяции; добавленный план сможет стать родителем со следующего поколения.
4. Если достигнут предел проверок, это записывается в журнал. Это не доказывает отсутствие других планов. После следующего поколения без новых особей попытка повторится.
5. Если поиск полностью завершен без нового плана, все допустимые размещения уже встречались в популяциях. Страница сообщает об этом. Такой поиск больше не повторяется, поскольку выбывшие планы возвращать нельзя. Это также может быть установлено при наборе начальной популяции. Повторения при исчерпанном наборе допустимых планов остаются; искусственные копии не добавляются.

В журнале это действие называется «Новый план после повторения популяции». Оно также срабатывает, если популяция сократилась и не получила новых особей. Дополнительный поиск работает независимо от включения мутаций и не меняет их вероятность. Если состав меняется, а лучшая стоимость стоит на месте, он не запускается. Число поколений остается критерием остановки; повторение само по себе не завершает расчет.

Построение нового плана использует прежнюю процедуру поиска с возвратом, без сторонних библиотек и новых настроек. Дополнительные проверки увеличивают время только в запусках с повторением популяций. Лучший найденный план сохраняется, но весь последующий ход случайного поиска меняется: сравнение со старой версией может дать меньшую, такую же или большую итоговую стоимость на отдельном запуске.

В режиме «Лучшая половина» прежняя популяция делится по стоимости в начале поколения: верхняя часть служит источником родителей, остальные особи — резервом. Число родителей равно половине фактической популяции с округлением вниз, но не меньше одной особи. Группа доступных родителей сохраняется до конца поколения. Если исправление не удалось, сразу берется самая дешевая еще не добавленная особь нижней половины и переносится без изменений. При исчерпании резерва пробуется следующая пара родителей. Верхняя половина не используется для замены неудачного потомка или заключительного переноса старых планов. Это не означает автоматическое сохранение всей верхней половины: по правилу элитизма обязательно сохраняется один лучший план.

При турнирном отборе резерв берется из всей прежней популяции среди особей, которые еще не добавлены и не выбирались родителями. Добавленная из резерва особь исключается из дальнейшего выбора родителей этого поколения. Родитель считается использованным сразу после выбора, даже если получить потомка не удалось. При отсутствии подходящего резерва пробуется следующая пара. В следующем поколении перенесенные планы снова участвуют в обычном отборе.

После ограниченного числа попыток скрещивания оставшиеся места также заполняются из резерва: только из нижней половины при соответствующем отборе либо из неиспользованных особей всей прежней популяции при турнире. Если их не хватает, пробуются новые размещения с исключением уже добавленных и выбывших планов; в режиме лучшей половины исключается вся родительская группа, в турнире — использованные родители. Если заданный размер собрать не удалось, используются найденные разные планы без копий; показатель «Разных планов» показывает фактическое количество и заданный размер. На этапах показаны число разных использованных родителей, общее количество перенесенных из прежней популяции особей и отдельно число добавлений из резерва после неудачного исправления.

Дополнительно запоминаются выбывшие планы: это допустимые размещения, которые были в популяции, но не вошли в следующее поколение. Они больше не допускаются в этом запуске. Исправление и добор исключают их внутри поиска; мутация пропускает такие варианты и пробует другие изменения. Потомок после скрещивания также отклоняется, если он совпал с выбывшим планом. При добавлении выполняется итоговая проверка. Лучший план сохраняется, а планы, непрерывно переходящие между поколениями, могут продолжать участвовать. При новом запуске список выбывших планов создается заново. Этот запрет может уменьшить фактическую популяцию: если новые разные размещения не найдены, размер остается меньше заданного максимума.

Для полного перебора сервер передает прогресс примерно дважды в секунду; остальные методы возвращают историю этапов после окончания расчета. Оценка оставшегося времени приблизительная: скорость меняется из-за разной сложности проверяемых назначений. Для перебора используется стандартный `itertools.product`; дополнительные пакеты не нужны.

На графике генетического метода горизонтальная ось показывает поколения, вертикальная — стоимость в рублях. Числовая шкала и линии сетки позволяют оценить снижение. Шкала стоимости подбирается по найденным значениям и может начинаться выше нуля. У ветвей и границ горизонтальная ось показывает число просмотренных узлов: расстояние между точками соответствует продвижению поиска, а не номеру сохраненного этапа. У полного перебора показаны сохраненные этапы. На графике отсечений вертикальная ось показывает их количество. На узком экране график можно прокручивать горизонтально.

## Подробности генетического поколения

После расчета откройте блок «Поколение N». Поколение можно выбрать из списка или кнопками вперед и назад. Поколение 0 показывает создание начальной популяции. В последующих поколениях доступны:

- Популяция до отбора: хромосомы, стоимость и участие в выборе родителей. В режиме лучшей половины видно, какие планы входят в родительскую группу, какие принадлежат резерву нижней половины и какие перенесены из него. При турнире отмечены планы, добавленные из резерва и исключенные из дальнейшего выбора родителей этого поколения.
- Все действия поколения, включая неудачные попытки: сохранение лучшего плана, скрещивания, исправления, мутации и добор.
- Для турнира — участники каждой из двух выборок, их стоимость и победители. Между отдельными турнирами участники могут повторяться.
- Таблица назначений по контейнерам: оба родителя, результат скрещивания, исправление и мутация. Измененные назначения отмечены рамкой. Недопустимый промежуточный план подписан; его стоимость не выдается за стоимость допустимого решения.
- Число проверок при исправлении, достижение предела 5 000 проверок, число попыток мутации и пропущенных выбывших вариантов. Внутренние узлы поиска исправления не записываются.
- После неудачного исправления — добавленный из резерва план в таблице назначений либо сообщение, что подходящего резерва нет. Добавление из резерва также записывается отдельным действием сразу за неудачным скрещиванием.
- Итоговая популяция, планы, выбывшие именно в этом поколении, и суммарное количество запрещенных выбывших планов.

Каждый план получает постоянный номер на время запуска. Сервер хранит хромосому один раз в общем списке `plans`; история поколений ссылается на номера. Это позволяет сопоставлять одинаковые размещения между действиями и уменьшает повторение данных в ответе. Номера получают и недопустимые промежуточные потомки, поэтому они не идут подряд внутри одной популяции. Подробный журнал включает все попытки скрещивания, даже если потомок отклонен или не удалось его исправить. Таблицы строятся при открытии блока в браузере. Запись журнала входит во время расчета.

## Дерево ветвей и границ

После расчета нажмите «Показать дерево». Каждый узел — частичное назначение: контейнер отправлен на указанную площадку, предыдущие назначения берутся из пути от корня. № показывает порядок проверки. В узле указаны уже набранная стоимость, нижняя оценка и действие алгоритма. Пунктир означает отсечение; темная рамка отмечает назначения итогового плана. Ползунок, кнопки шагов и нажатие на узел позволяют восстановить ход поиска.

Управление просмотром:

- Масштаб задается числом от 1 до 300% или кнопками «−» и «+». При изменении масштаба сохраняется место, которое вы рассматриваете.
- Перетаскивайте свободный фон мышью, чтобы перемещаться по схеме. Можно использовать и полосы прокрутки.
- Ctrl + колесо меняет масштаб вокруг указателя.
- «Вписать дерево» подбирает масштаб для всех узлов, показанных к выбранному шагу. При первом открытии схема вписывается автоматически.
- «К корню» и «К текущему шагу» перемещают область просмотра, сохраняя выбранный шаг и масштаб. Стрелка в узле отмечает текущий шаг.

Схема создается один раз при первом открытии. При выборе шага меняются только видимость и выделение узлов; при изменении масштаба меняется размер SVG. Повторно строить все дерево для каждого действия не требуется.

Сохраняются первые 500 шагов, включая отклоненные назначения по ресурсам. Это предел записи схемы, а не предел расчета: сам метод продолжает работать до своего лимита узлов или завершения поиска. Если схема неполная, страница сообщает об этом. При остановке расчета по лимиту непроверенные продолжения не изображаются. Будущие шаги не появляются на схеме, пока ползунок не дошел до них.

Это метод ветвей и границ с обходом в глубину. Для очередного контейнера сначала проверяется площадка из лучшего известного допустимого плана, затем остальные площадки по стоимости. Если начального плана нет, все площадки сразу проверяются по стоимости. Так поиск начинает с продолжений, близких к уже допустимому размещению, и раньше получает новые полные планы. Остальные назначения не отбрасываются только из-за их порядка: после возврата метод проверяет и другие ветви, если их не отсекли ограничения или нижняя оценка.

Нижняя оценка равна уже набранной стоимости плюс сумме самых дешевых еще подходящих назначений оставшихся контейнеров. В оценке контейнеры рассматриваются независимо, поэтому они могут претендовать на один и тот же остаток ресурсов. Оценка может быть ниже реально достижимой стоимости, но не выше нее. Если она уже не меньше стоимости известного допустимого плана, продолжение отсекается. При отсутствии места для оставшегося контейнера ветвь также отсекается. Минимальная стоимость подтверждается только после завершения поиска без остановки по лимиту.

Показатель «Улучшений» считает обновления лучшего плана к выбранному этапу; первый найденный план при отсутствии начального также считается обновлением. Горизонтальная линия стоимости допустима: либо за лимит не найдено более дешевого плана, либо полный поиск подтвердил минимальную стоимость исходного. Интерфейс различает эти случаи. Если применить результат генетического метода к текущему размещению вручную, он становится обычным текущим планом; автоматической передачи результатов между методами нет.

На примере 25 контейнеров / 5 площадок, зерно данных 26, прежний порядок за 100 000 узлов не улучшал исходную стоимость 118 090. После изменения порядка за тот же лимит найден план стоимостью 109 960. Поиск еще не завершен, минимальная стоимость не доказана. Ограниченный поиск не обязан найти такой же результат, как генетический метод; увеличение лимита позволяет проверить больше ветвей, но само по себе не гарантирует улучшения.

## Время расчета

В результатах всех трех методов показано время работы Python в секундах. Сервер измеряет его через `time.perf_counter()`: от начала вызова метода, включая подготовку данных и проверку результата, до его возврата. Передача ответа и отрисовка браузером в это время не входят. Для потокового полного перебора время измеряется внутри метода; оно также включает запуск и ожидание рабочих процессов.

Пока идет расчет, браузер показывает прошедшее время ожидания и обновляет его каждые 250 мс. Оно может быть немного больше серверного времени. У ручного плана отдельно показано время последнего пересчета стоимости и ограничений. Время не влияет на случайные числа генетического алгоритма или критерии остановки методов.

Браузер отправляет данные задачи на /api/evaluate для пересчета. Запуск метода отправляет те же данные на /api/solve. Скрипты tree.js и generation.js подключены после app.js и используют его простые функции создания элементов и форматирования чисел; отдельные библиотеки для просмотра не нужны.

## Проверка

~~~powershell
py -3 -B -m unittest -q
~~~

Тесты проверяют ограничения, формулу стоимости, допустимость найденных планов, полный перебор более миллиона назначений и статусы точных методов. Для ветвей и границ есть пример, в котором жадный выбор дает стоимость 101, а поиск другой ветви — 20. Нижние оценки и отсечения записанного дерева проверяются независимым перебором всех продолжений маленькой задачи.

Для генетического алгоритма также проверяются запрет возвращения выбывших планов через исправление, мутацию и добор, соответствие журнала итоговой популяции, выбор победителей турнира и стоимость каждого показанного допустимого плана. Для резерва проверяются выбор самой дешевой подходящей особи и немедленное добавление после неудачного исправления. В режиме лучшей половины переносы разрешены только из нижней части, а доступная группа родителей остается постоянной. При турнире перенесенные резервные планы исключаются из выбора родителей. Отдельный пример с 40 контейнерами и 10 площадками проверяет набор 36 начальных планов с бюджетом более пяти миллионов проверок.

На маленькой задаче проверяется, что исправление сначала пробует назначения потомка и сохраняет два из трех назначений, когда достаточно перенести один контейнер. Отдельный пример проверяет отсутствие копий при исчерпанном резерве.
