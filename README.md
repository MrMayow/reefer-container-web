# Размещение рефрижераторных контейнеров

## Репозиторий и работа с версиями

Это самостоятельный проект в приватном репозитории [MrMayow/reefer-container-web](https://github.com/MrMayow/reefer-container-web). Папка уже содержит локальный Git-репозиторий: ветка `main` связана с `origin/main`. Изменения нужно вносить именно в эту папку, а не в её родительский каталог с прежней копией файлов.

После очередного изменения откройте PowerShell в папке `reefer-container-web` и выполните:

```powershell
git status
git diff
py -3 -B -m unittest -q
git add .
git commit -m "Краткое описание изменения"
git push
```

`git status` показывает изменённые файлы, `git diff` — что именно изменилось, тесты проверяют работу программы, `git commit` сохраняет версию локально, а `git push` отправляет её на GitHub. Если изменения внесены на GitHub или другом компьютере, перед началом работы выполните `git pull --ff-only`. GitHub хранит исходный код; для запуска приложения нужен `app.py` на компьютере или Python-сервере, потому что расчёты выполняются в Python.

Первый локальный вариант учебного веб-приложения. Он позволяет редактировать исходные данные, генерировать заведомо допустимый пример, вручную размещать контейнеры, сразу видеть стоимость и нарушения ограничений, запускать генетический алгоритм, метод ветвей и границ и полный перебор. Все числовые параметры и результаты в этой версии **целые**; дробный ввод отклоняется.

## Запуск в Windows

Нужен Python 3. Сторонние пакеты не требуются. Откройте PowerShell **в папке проекта** и выполните:

```powershell
py -3 --version
py -3 app.py
```

Если команда `py` не найдена, но установлен Python, используйте `python --version` и `python app.py`. После сообщения `Откройте http://127.0.0.1:8000/` перейдите в браузере по этому адресу. Для остановки нажмите `Ctrl+C` в окне PowerShell. Если порт 8000 занят, запустите `py -3 app.py 8001` и откройте `http://127.0.0.1:8001/`.

После изменения файлов Python остановите прежний сервер сочетанием `Ctrl+C`, запустите его снова и обновите страницу браузера. Вторая копия сервера на том же порту теперь не запускается: это предотвращает ситуацию, когда новый интерфейс получает ответы от старого алгоритма.

Открывать `static/index.html` двойным щелчком не нужно: страница обращается к локальному Python-серверу. Сервер слушает только `127.0.0.1`, то есть ваш компьютер.

## Первые действия

1. После запуска появится пример из 12 контейнеров и 3 площадок. Его начальное распределение допустимо по всем ограничениям; оно **не заявлено как оптимальное**.
2. Зажмите контейнер и перетащите его мышью или пальцем на другую площадку. Во время переноса появятся «плавающая» карточка и подсветка площадки под указателем. Можно также выбрать контейнер щелчком, затем щёлкнуть по площадке или сменить её в таблице «Стоимость по контейнерам». Для управления с клавиатуры выберите кнопку контейнера, переведите фокус на площадку и нажмите Enter.
3. Посмотрите на общую стоимость, стоимость каждой площадки и список нарушений. Программа позволяет временно сделать недопустимый план, чтобы было видно, какое ограничение нарушено. Такой план нельзя считать решением задачи.
4. Измените массу или мощность контейнера, лимиты площадки, время или тариф. Расчёт выполняется после изменения поля. Кнопки `+` добавляют объект, `×` удаляет его. Удаление площадки оставит её контейнеры неназначенными.
5. Укажите количество контейнеров и площадок, а затем нажмите «Сгенерировать». Одинаковое «зерно» при тех же размерах повторит набор. Генерация заменит текущие данные, поэтому сначала запишите нужные значения отдельно.
6. Переключите единицы тарифа перевозки при необходимости. Условия учебной задачи пока не уточнили их окончательно.
7. Откройте вкладку «Генетический алгоритм», задайте число поколений, размер популяции и зерно, затем нажмите «Запустить поиск». График показывает лучшую допустимую стоимость после каждого поколения. Ползунком выберите поколение: ниже отобразятся его стоимость, число разных планов, операций и размещение контейнеров. Кнопка «Применить лучший итоговый план» перенесёт найденное назначение на основную схему. После этого контейнеры снова можно двигать вручную и сравнивать стоимость. Изменение исходных параметров сбрасывает старый результат поиска; ручной перенос его сохраняет для сравнения.
8. Откройте вкладку «Ветви и границы», задайте лимит узлов и нажмите «Запустить точный поиск». Первый график показывает лучшую допустимую стоимость, второй — накопление отсечённых ветвей; ползунок открывает снимки поиска. Итог может быть доказанным оптимумом, доказанным отсутствием решения либо незавершённым поиском по лимиту. Найденный план можно применить к основной схеме. Если вы хотите передать генетический план как стартовую верхнюю границу, сначала запустите генетический метод, затем **установите отметку** «Использовать результат генетического алгоритма как начальный план» во вкладке ветвей и границ. По умолчанию отметка снята.
9. Откройте вкладку «Полный перебор» и нажмите «Запустить полный перебор». Программа проверит назначения одно за другим. График показывает лучшую стоимость, ползунок — снимки работы, а счётчики и полоска — количество проверенных, допустимых и недопустимых вариантов. У примера с 12 контейнерами и 3 площадками всего 3¹² = 531 441 вариант, поэтому лимита 1 000 000 достаточно для доказанного ответа. Для большей задачи может потребоваться повысить лимит до 5 000 000 или использовать метод ветвей и границ. Кнопка применения переносит найденный план на схему.

## Что находится в файлах

| Файл | Роль |
| --- | --- |
| `static/index.html` | Разметка страницы: заголовки, поля, таблицы и области визуализации. |
| `static/style.css` | Холодная однотонная палитра, расположение блоков и адаптация под узкий экран. |
| `static/app.js` | Реакция на действия пользователя: изменение полей, перенос контейнера, запрос расчёта, обновление страницы. |
| `app.py` | Локальный HTTP-сервер; отдаёт страницу и принимает JSON-запросы. |
| `model.py` | Создание данных, проверка ограничений, расчёт стоимости; место для будущих алгоритмов. |
| `genetic.py` | Генетический поиск допустимого размещения и фактическая история поколений. |
| `branch_bound.py` | Точный поиск с нижней оценкой, отсечением ветвей и записью этапов. |
| `exhaustive.py` | Полный перебор всех назначений без отсечения ветвей, со счётчиками и историей. |
| `test_model.py` | Несколько проверок ключевых правил модели. |
| `test_genetic.py` | Проверки допустимости показанных этапов, сохранения лучшего плана и воспроизводимости. |
| `test_branch_bound.py` | Сравнение с полным перебором и проверка статусов доказательства. |
| `test_exhaustive.py` | Проверки полного перебора, этапов, лимита и доказательства. |

Связь частей: браузер загружает HTML, CSS и JS с `app.py`. JavaScript хранит текущие данные страницы в объекте `task`. После изменения он отправляет `task` запросом `POST /api/evaluate`. `app.py` передаёт данные в `model.evaluate`, получает ответ и возвращает JSON. JavaScript показывает ответ в схеме, списке нарушений и таблице стоимости. Перезагрузка страницы восстановит исходный пример: сохранение пока не добавлено.

Другие адреса: `GET /api/example` возвращает начальный набор; `POST /api/generate` получает `containerCount`, `siteCount`, `seed`; `POST /api/solve` получает `method`, `task` и `options`. Для генетического метода в `options` задаются `generations`, `populationSize`, `seed`; для метода ветвей и границ — `nodeLimit` и, только по выбору пользователя, `incumbentAssignment`; для полного перебора — `combinationLimit`. Ответ содержит итог и историю реальных этапов.

## Математическая модель

Каждый контейнер должен находиться **ровно на одной** площадке. Для площадки проверяются число мест, общая масса и подключённая мощность. Для каждого контейнера также проверяется `время перевозки площадки + время хранения контейнера ≤ C`.

Поле `d` допускает два толкования, потому что окончательные единицы ещё не подтверждены:

- `₽ / контейнер·ч`: стоимость `tᵢ × hⱼ + Tⱼ × dⱼ`;
- `₽ / т·ч`: стоимость `tᵢ × hⱼ + wᵢ × Tⱼ × dⱼ`.

Здесь `tᵢ` — время хранения, `hⱼ` — тариф хранения, `Tⱼ` — время перевозки, `wᵢ` — масса. Общая стоимость равна сумме по назначенным контейнерам. Если контейнер не назначен, показанная сумма является **частичной**, а план помечается как недопустимый. Отдельный тариф электроэнергии в исходной постановке отсутствует, поэтому мощность служит только ограничением.

Модель резервирует ресурсы площадки под всю назначенную партию. Она не моделирует освобождение мест по часам, очереди, технику и отключение питания.

## Как работает генерация

Для контейнеров берутся целые положительные масса (12–29 т), мощность (4–9 кВт) и время хранения (9–27 ч). Время перевозки площадки тоже целое: 1, 2, 3 ч и так далее. Контейнеры распределяются по площадкам, после чего целочисленные лимиты каждой площадки задаются немного выше фактической нагрузки, число мест — на одно больше. Значение `C` выбирается не ниже наибольшей суммы времени хранения и перевозки в созданном назначении. Поэтому **начальный план генератора допустим**. Это не гарантия, что любые последующие ручные перестановки будут допустимыми.

В прототипе допустимо от 1 до 80 контейнеров и от 1 до 10 площадок. Эти пределы нужны для удобства интерфейса и не являются частью математической постановки.

## Как работает генетический алгоритм

Одна особь популяции — список номеров площадок, по одному номеру на каждый контейнер. Сначала Python проверяет данные и вычисляет допустимые площадки и стоимость каждой пары «контейнер — площадка». Если текущий ручной план допустим, он входит в первую популяцию: результат поиска не может оказаться дороже него. Остальные особи строятся случайным жадным способом, начиная с контейнеров, для которых меньше допустимых площадок. Если при начальном поиске план не найден, приложение сообщает именно «не найден», а не «решения нет».

На каждом поколении турнир из трёх случайных особей выбирает родителя с меньшей стоимостью. Для каждого контейнера новый план получает площадку одного из двух родителей. Если после скрещивания нарушились ограничения, алгоритм пытается собрать допустимый план с приоритетом выбранных площадок; если это не удалось, берёт лучшего родителя. Затем возможна мутация: перенос одного контейнера либо обмен площадками двух контейнеров. Мутация принимается только после проверки всех ограничений. Лучший план копируется в следующее поколение без изменений (элитизм). Поэтому график лучшей стоимости не поднимается вверх.

Сервер записывает для поколений от нулевого до последнего лучший допустимый план, его целочисленную стоимость, число разных планов, скрещиваний, успешных мутаций и исправлений. Браузер строит по этим записям SVG-график и схему выбранного поколения. Это фактические результаты одного запуска; прогресс показывается после завершения расчёта, без потоковой передачи. Зерно делает повтор запуска с теми же данными и настройками воспроизводимым. По умолчанию используется 60 поколений и 36 особей; разрешено 1–200 поколений и 4–80 особей. Большие значения требуют больше времени.

Генетический алгоритм — эвристика: найденный план допустим, но **глобальный оптимум не доказан**. Он также не доказывает отсутствие решения, если поиск его не нашёл.

## Как работает метод ветвей и границ

Одна ветвь последовательно назначает контейнеры на площадки. Сначала обрабатываются контейнеры с меньшим числом подходящих площадок и большей нагрузкой. Для каждой пары заранее вычисляется стоимость; площадки перебираются от более дешёвой к более дорогой. Текущий допустимый ручной план служит первой верхней оценкой, если он есть. Если его нет, поиск создаёт первый допустимый план сам.

В узле дерева Python проверяет свободные места, массу, мощность и срок. Неподходящая ветвь отсекается. Для оставшихся контейнеров вычисляется **нижняя оценка**: их минимальная возможная стоимость при текущих свободных ресурсах, причём конкуренция между ними за одни ресурсы временно игнорируется. Поэтому оценка может быть слишком оптимистичной, но никогда не превышает настоящую минимальную стоимость продолжения ветви. Если даже эта оценка не лучше уже найденного плана, всю ветвь можно отбросить без потери оптимума.

На вкладке показываются реальные снимки поиска: число просмотренных узлов, отсечений по оценке и ресурсам, глубина ветви, лучшая стоимость и распределение контейнеров на выбранном этапе. Первый график показывает, как улучшался лучший допустимый план. Он может быть горизонтальным, если за просмотренные узлы более дешёвый план не найден. Второй график показывает накопление отсечений и позволяет увидеть ход перебора даже при неизменной цене. «Нижняя оценка в начале» относится к корню дерева и остаётся безопасной нижней границей; она не выдаётся за текущую оценку всего незавершённого поиска. История появляется после окончания запроса, без потоковой передачи.

По умолчанию метод просматривает не более 100 000 узлов; допустим диапазон 1–1 000 000. Если все ветви проверены или отсечены, программа сообщает **«глобальный оптимум доказан»** либо **«допустимого размещения нет»**. Если достигнут лимит, она показывает лучший найденный план, если он есть, но **не заявляет доказательство**. Передача плана ГА выполняется только при установленной отметке и повторно проверяется на сервере по всем ограничениям. Без отметки метод использует текущий план на основной схеме как начальную верхнюю границу, если он допустим. Если вы ранее применили план ГА к этой схеме, он уже стал текущим планом; это отдельное действие пользователя. Передача помогает поиску, но сама по себе не доказывает оптимум. Для больших задач точный поиск может быть дорогим, поэтому лимит нужен для управляемого времени работы. После изменения исходных параметров старый результат и выбор передачи сбрасываются; ручная перестановка сохраняет старые результаты для сравнения.

Например, на сгенерированном наборе из 20 контейнеров и 3 площадок с зерном 26 генетический метод нашёл план стоимостью 61 836 ₽, а отдельный запуск ветвей и границ остановился по лимиту с планом 63 746 ₽. Это **не был доказанный оптимум**. Если установить отметку передачи плана ГА, при том же лимите точный поиск начнёт с 61 836 ₽ и не вернёт более дорогой план. Если оставить отметку снятой, методы можно сравнивать как независимые запуски. Прямая линия стоимости означает, что за просмотренные узлы улучшения не было; второй график показывает выполнявшееся отсечение ветвей.

## Как работает полный перебор

Для каждого из `n` контейнеров Python по очереди выбирает одну из `m` площадок. Получается `mⁿ` полных назначений. Например, для 12 контейнеров и 3 площадок это 531 441 вариант. Алгоритм проверяет **каждый** вариант, включая нарушающие ограничения. Недопустимые варианты входят в счётчик проверок, но не сравниваются по стоимости. Среди допустимых запоминается самый дешёвый. Здесь нет нижней оценки, отсечения ветвей или использования результата другого метода.

Вкладка показывает реальную историю: после части проверок — число просмотренных, допустимых и недопустимых назначений, лучшую найденную стоимость и соответствующее размещение. Полоска показывает долю проверенного пространства. История и график появляются после ответа сервера; отображения в реальном времени пока нет. Число всех назначений передаётся в ответе строкой, чтобы JavaScript точно показывал даже очень большое целое число.

Лимит по умолчанию — 1 000 000 полных назначений, допустимый диапазон — от 1 до 5 000 000. Если проверены все `mⁿ`, алгоритм **доказывает** оптимальность лучшего плана или отсутствие допустимого плана. Если сработал лимит, найденный план остаётся только лучшим среди просмотренных, а отсутствие плана не означает неразрешимости. При большом `mⁿ` полный перебор быстро становится дорогим: например, для 20 контейнеров и 3 площадок требуется проверить 3 486 784 401 назначение. Метод ветвей и границ может закончить раньше за счёт безопасного отсечения.

## Проверка

В PowerShell из папки проекта:

```powershell
py -3 -m unittest -v
```

Тесты проверяют допустимость автоматически созданного плана, обязательное назначение, четыре жёстких ограничения, обе формулы тарифа, допустимость показанных этапов поиска, сохранение лучшей стоимости, воспроизводимость генетического метода, совпадение точных методов на маленьких задачах и правильный статус при лимите. Для ручной проверки откройте страницу, перенесите контейнер, посмотрите стоимость, затем уменьшите число мест одной площадки до нуля: она должна показать нарушение. После восстановления данных запустите три алгоритма, переключите этапы и примените найденные планы.
