# Размещение рефрижераторных контейнеров

Веб-приложение распределяет контейнеры по площадкам с минимальной стоимостью. Можно задать данные вручную, сгенерировать пример, перетаскивать контейнеры и сравнивать три метода поиска. Все числовые параметры задаются целыми числами.

## Запуск

Нужен Python 3. Дополнительные пакеты не требуются. Откройте PowerShell в папке проекта:

~~~powershell
py -3 app.py
~~~

Откройте http://127.0.0.1:8000/ . Остановка сервера — Ctrl+C. Если порт занят, запустите «py -3 app.py 8001» и откройте порт 8001. После изменения Python-файлов перезапустите сервер. Открывать HTML-файл напрямую не нужно: браузер обращается к Python-серверу.

## Работа с Git

Проект находится в приватном репозитории [MrMayow/reefer-container-web](https://github.com/MrMayow/reefer-container-web). Рабочая папка — reefer-container-web. После изменений:


## Использование

1. Перетащите контейнер на площадку мышью или пальцем. Другой способ — нажать контейнер, затем площадку. Назначение также меняется в таблице стоимости. Сумма и нарушения пересчитываются.
2. Измените параметры в таблицах или нажмите «Сгенерировать». Одинаковое зерно генерации создаёт одинаковые данные. Генерация заменяет текущий набор.
3. Выберите метод, задайте его настройки и нажмите «Запустить». После расчёта появятся график, ползунок этапов, счётчики и размещение контейнеров. Кнопка «Применить лучший план» переносит найденный вариант на схему. Во время полного перебора показываются число проверенных назначений, средняя скорость, прошедшее и примерное оставшееся время. Кнопка «Остановить» прерывает расчёт без результата. Поле «Процессы» задаёт число одновременно работающих процессов; 0 выбирает число автоматически.

Изменение параметров сбрасывает результаты старых запусков. Ручное перемещение сохраняет их для сравнения. Обновление страницы возвращает исходный пример; постоянное сохранение данных пока не предусмотрено.

## Условия и стоимость

Каждый контейнер должен быть назначен ровно на одну площадку. На площадке ограничены число мест, суммарная масса и мощность. Для каждого контейнера проверяется срок: время хранения + время перевозки не больше предельного времени.

Стоимость контейнера равна времени хранения × тарифу хранения + стоимости перевозки. Для перевозки есть два режима: тариф за контейнер-час или тариф за тонну-час. Во втором режиме стоимость перевозки дополнительно умножается на массу контейнера. Если план нарушает ограничения, показанная сумма не считается допустимым решением.

## Методы поиска

Настройка «Максимальный размер популяции» в генетическом алгоритме задаёт верхний предел количества разных планов в одном поколении. Алгоритм старается набрать это количество, но может использовать меньше планов, если за ограниченное число попыток собрать полный набор не удалось. Например, при пределе 36 фактическая популяция может содержать 8 планов. Это не означает, что всего существует только 8 допустимых размещений.

При создании начальной популяции уже найденные планы исключаются внутри поиска, чтобы возвращаться к другим назначениям. На старт отведено до 20 попыток на каждое заданное место, до 100 000 проверок назначений за одну попытку и до 5 000 000 проверок суммарно. Поиск заканчивается раньше, если набрана популяция или полностью проверены все оставшиеся варианты. В этапе 0 показаны число попыток и проверок начального поиска. В режиме «Лучшая половина» эта половина служит источником родителей: пары могут выбираться многократно, поэтому число потомков может превышать число родителей. Размер следующих поколений ограничивается заданным максимумом.

- **Генетический алгоритм** создаёт допустимые планы, скрещивает их и меняет назначения. При создании планов он возвращается к предыдущим контейнерам и пробует другие площадки, если текущий выбор приводит к тупику; это помогает получить разные планы при тесных ограничениях. В настройке «Отбор родителей» можно выбрать турнир из трёх случайных планов (побеждает самый дешёвый; режим по умолчанию) или выбор родителей из лучшей половины популяции после сортировки по стоимости. Мутации можно выключить или выбрать один тип: перенос одного контейнера либо обмен площадками двух контейнеров. Вероятность попытки мутации для каждого потомка задаётся целым числом от 0 до 100%; попытка не гарантирует допустимое изменение. По умолчанию это 60% и включён обмен. Лучший план сохраняется в каждом поколении. График показывает лучшую стоимость по поколениям. Генетический поиск не гарантирует нахождения плана с минимальной стоимостью.
- **Ветви и границы** перебирает назначения и отсекает ветви, которые не могут улучшить лучший план. Отдельный график показывает число отсечений. После завершения всего поиска метод подтверждает минимальную стоимость или отсутствие допустимого решения. При достижении лимита узлов доказательства нет. Результат генетического алгоритма передаётся как начальный план только при установленной отметке.
- **Полный перебор** проверяет все назначения без отсечения и без лимита проверок. Большие задачи распределяются между несколькими процессами, чтобы использовать ядра процессора. Для небольших задач автоматический режим выбирает один процесс, потому что запуск дополнительных процессов может быть медленнее самого поиска. После проверки всех вариантов результат доказан. Для 12 контейнеров и 3 площадок всего 3¹² = 531 441 назначение. Время работы быстро растёт с числом контейнеров и площадок: для N контейнеров и M площадок нужно проверить Mᴺ назначений.

В генетическом алгоритме каждая популяция содержит только разные допустимые планы. Исправление пропускает уже добавленные размещения; после мутации потомок также проверяется на повтор. Лучший план сохраняется отдельно по правилу элитизма. Турнир при небольшой популяции использует до трёх участников.

Если исправление не удалось, сразу берётся самая дешёвая особь прежней популяции среди тех, которые ещё не добавлены в новое поколение и не выбирались родителями. Она добавляется из резерва без изменений и исключается из дальнейшего выбора родителей этого поколения. При отборе из лучшей половины резерв может браться и из оставшейся половины. Родитель считается использованным сразу после выбора, даже если получить потомка не удалось. Если подходящего резерва нет, пробуется следующая пара родителей. В следующем поколении добавленный из резерва план снова участвует в обычном отборе.

После ограниченного числа попыток скрещивания оставшиеся места также заполняются самыми дешёвыми неиспользованными особями прежней популяции. Если их не хватает, пробуются новые размещения с исключением использованных родителей и уже добавленных планов. Если заданный размер собрать не удалось, используются найденные разные планы без копий; показатель «Разных планов» показывает фактическое количество и заданный размер. На этапах показаны число разных использованных родителей, общее количество перенесённых из прежней популяции особей и отдельно число добавлений из резерва после неудачного исправления.

Дополнительно запоминаются выбывшие планы: это допустимые размещения, которые были в популяции, но не вошли в следующее поколение. Они больше не допускаются в этом запуске. Исправление и добор исключают их внутри поиска; мутация пропускает такие варианты и пробует другие изменения. Потомок после скрещивания также отклоняется, если он совпал с выбывшим планом. При добавлении выполняется итоговая проверка. Лучший план сохраняется, а планы, непрерывно переходящие между поколениями, могут продолжать участвовать. При новом запуске список выбывших планов создаётся заново. Этот запрет может уменьшить фактическую популяцию: если новые разные размещения не найдены, размер остаётся меньше заданного максимума.

Для полного перебора сервер передаёт прогресс примерно дважды в секунду; остальные методы возвращают историю этапов после окончания расчёта. Оценка оставшегося времени приблизительная: скорость меняется из-за разной сложности проверяемых назначений. Для перебора используется стандартный `itertools.product`; дополнительные пакеты не нужны.

На графике генетического метода горизонтальная ось показывает поколения, вертикальная — стоимость в рублях. Числовая шкала и линии сетки позволяют оценить снижение; под графиком указаны стоимости поколения 0 и последнего поколения, разница в рублях и процентах. Шкала стоимости подбирается по найденным значениям и может начинаться выше нуля. У других методов горизонтальная ось показывает сохранённые этапы; на графике отсечений вертикальная ось показывает их количество. На узком экране график можно прокручивать горизонтально.

## Подробности генетического поколения

После расчёта откройте «Подробно о поколении». Поколение можно выбрать из списка или кнопками вперёд и назад. Поколение 0 показывает создание начальной популяции. В последующих поколениях доступны:

- Популяция до отбора: хромосомы, стоимость и участие в выборе родителей. В режиме лучшей половины видно, какие планы исключены из выбора родителей. Отдельно отмечены планы, добавленные из резерва и исключённые из дальнейшего выбора родителей этого поколения.
- Все действия поколения, включая неудачные попытки: сохранение лучшего плана, скрещивания, исправления, мутации и добор.
- Для турнира — участники каждой из двух выборок, их стоимость и победители. Между отдельными турнирами участники могут повторяться.
- Таблица назначений по контейнерам: оба родителя, результат скрещивания, исправление и мутация. Изменённые назначения отмечены рамкой. Недопустимый промежуточный план подписан; его стоимость не выдаётся за стоимость допустимого решения.
- Число проверок при исправлении, достижение предела 5 000 проверок, число попыток мутации и пропущенных выбывших вариантов. Внутренние узлы поиска исправления не записываются.
- После неудачного исправления — добавленный из резерва план в таблице назначений либо сообщение, что подходящего резерва нет. Добавление из резерва также записывается отдельным действием сразу за неудачным скрещиванием.
- Итоговая популяция, планы, выбывшие именно в этом поколении, и суммарное количество запрещённых выбывших планов.

Каждый план получает постоянный номер на время запуска. Сервер хранит хромосому один раз в общем списке `plans`; история поколений ссылается на номера. Это позволяет сопоставлять одинаковые размещения между действиями и уменьшает повторение данных в ответе. Номера получают и недопустимые промежуточные потомки, поэтому они не идут подряд внутри одной популяции. Подробный журнал включает все попытки скрещивания, даже если потомок отклонён или не удалось его исправить. Таблицы строятся при открытии блока в браузере. Запись журнала входит во время расчёта.

## Дерево ветвей и границ

После расчёта нажмите «Показать дерево поиска». Каждый узел — частичное назначение: контейнер отправлен на указанную площадку, предыдущие назначения берутся из пути от корня. № показывает порядок проверки. В узле указаны уже набранная стоимость, нижняя оценка и действие алгоритма. Пунктир означает отсечение; тёмная рамка отмечает назначения итогового плана. Ползунок, кнопки шагов и нажатие на узел позволяют восстановить ход поиска.

Управление просмотром:

- Масштаб задаётся числом от 1 до 300% или кнопками «−» и «+». При изменении масштаба сохраняется место, которое вы рассматриваете.
- Перетаскивайте свободный фон мышью, чтобы перемещаться по схеме. Можно использовать и полосы прокрутки.
- Ctrl + колесо меняет масштаб вокруг указателя.
- «Вписать дерево» подбирает масштаб для всех узлов, показанных к выбранному шагу. При первом открытии схема вписывается автоматически.
- «К корню» и «К текущему шагу» перемещают область просмотра, сохраняя выбранный шаг и масштаб. Стрелка в узле отмечает текущий шаг.

Схема создаётся один раз при первом открытии. При выборе шага меняются только видимость и выделение узлов; при изменении масштаба меняется размер SVG. Повторно строить всё дерево для каждого действия не требуется.

Сохраняются первые 500 шагов, включая отклонённые назначения по ресурсам. Это предел записи схемы, а не предел расчёта: сам метод продолжает работать до своего лимита узлов или завершения поиска. Если схема неполная, страница сообщает об этом. При остановке расчёта по лимиту непроверенные продолжения не изображаются. Будущие шаги не появляются на схеме, пока ползунок не дошёл до них.

Это метод ветвей и границ с обходом в глубину. Сначала проверяются дешёвые площадки, но после возврата проверяются и другие назначения. Нижняя оценка равна уже набранной стоимости плюс сумме самых дешёвых ещё подходящих назначений оставшихся контейнеров. В оценке контейнеры рассматриваются независимо, поэтому они могут претендовать на один и тот же остаток ресурсов. Оценка может быть ниже реально достижимой стоимости, но не выше неё. Если она уже не меньше стоимости известного допустимого плана, продолжение отсекается. При отсутствии места для оставшегося контейнера ветвь также отсекается. Минимальная стоимость подтверждается только после завершения поиска без остановки по лимиту.

## Время расчёта

В результатах всех трёх методов показано время работы Python в секундах. Сервер измеряет его через `time.perf_counter()`: от начала вызова метода, включая подготовку данных и проверку результата, до его возврата. Передача ответа и отрисовка браузером в это время не входят. Для потокового полного перебора время измеряется внутри метода; оно также включает запуск и ожидание рабочих процессов.

Пока идёт расчёт, браузер показывает прошедшее время ожидания и обновляет его каждые 250 мс. Оно может быть немного больше серверного времени. У ручного плана отдельно показано время последнего пересчёта стоимости и ограничений. Время не влияет на случайные числа генетического алгоритма или критерии остановки методов.

Скрипты tree.js и generation.js подключены после app.js и используют его простые функции создания элементов и форматирования чисел; отдельные библиотеки для просмотра не нужны.

## Проверка

~~~powershell
py -3 -B -m unittest -q
~~~

Тесты проверяют ограничения, обе формулы тарифа, допустимость найденных планов, полный перебор более миллиона назначений и статусы точных методов. Для ветвей и границ есть пример, в котором жадный выбор даёт стоимость 101, а поиск другой ветви — 20. Нижние оценки и отсечения записанного дерева проверяются независимым перебором всех продолжений маленькой задачи.

Для генетического алгоритма также проверяются запрет возвращения выбывших планов через исправление, мутацию и добор, соответствие журнала итоговой популяции, выбор победителей турнира и стоимость каждого показанного допустимого плана. Для резерва проверяются выбор самой дешёвой неиспользованной особи, её немедленное добавление после неудачного исправления и исключение из дальнейшего выбора родителей этого поколения.
